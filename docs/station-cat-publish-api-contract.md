# Station Cat Publish API Contract

Status: Phase 18B active contract.

This document describes the software-side contract generated by NovelForge AI for the Station Cat website backend. Phase 18B sends this request to Station Cat when a publish target has both an API Base URL and a saved Station Cat Publish Token.

## Endpoint

Recommended endpoint:

```http
POST /api/novelforge/import
Authorization: Bearer <publish-token>
Content-Type: application/json
X-NovelForge-Contract: station-cat-novelforge-import.v1
```

Production API Base URL:

```text
https://wwwstationcat.org
```

Actual import endpoint:

```text
POST https://wwwstationcat.org/api/novelforge/import
```

The website backend reads the same token value from:

```text
NOVELFORGE_PUBLISH_TOKEN
```

In the app UI, enter that value into the `Station Cat Publish Token` field for the target.

The app accepts these API Base URL variants and normalizes them to the import endpoint:

- `https://wwwstationcat.org`
- `https://wwwstationcat.org/api/novelforge`
- `https://wwwstationcat.org/api/novelforge/import`

## Request

The request body never contains the publish token. Tokens are sent only through the `Authorization` header.

```json
{
  "contract": "station-cat-novelforge-import",
  "contractVersion": 1,
  "requestId": "novelforge:project_1:abcdef1234567890",
  "mode": "draft",
  "onlyChanged": true,
  "source": {
    "app": "NovelForge AI",
    "packageFormat": "novelforge-standard-publish-package",
    "packageVersion": 1,
    "generatedAt": "2026-06-18T05:00:00.000Z"
  },
  "publishPackage": {
    "format": "novelforge-standard-publish-package",
    "version": 1,
    "generatedAt": "2026-06-18T05:00:00.000Z",
    "project": {},
    "chapters": [],
    "cover": {},
    "pricingSuggestion": {}
  },
  "changedItems": [
    {
      "localType": "chapter",
      "localId": "chapter_1",
      "label": "第 1 章：第一封短信",
      "contentHash": "sha256-content-hash",
      "remoteId": null,
      "changeType": "create",
      "payload": {}
    }
  ]
}
```

### Modes

- `draft`: import or update content as a backend draft. This should be the default.
- `publish`: publish directly after import. The website should still enforce its own permission and validation rules.

### Changed Items

`changedItems` contains only the local records the app believes should be synced:

- `localType`: `project`, `cover`, or `chapter`.
- `localId`: stable local id from NovelForge.
- `remoteId`: previous Station Cat id if already known, otherwise `null`.
- `contentHash`: stable content hash generated by NovelForge.
- `changeType`: `create` or `update`.
- `payload`: the exact project, cover, or chapter object for this changed item.

The website should return the remote id for each accepted item so a later phase can persist remote ids into `PublishSyncState`.

## Success Response

```json
{
  "ok": true,
  "remoteBookId": "work_123",
  "previewUrl": "https://wwwstationcat.org/admin-v2/?contentId=123",
  "publishUrl": "https://wwwstationcat.org/zh-hant/works/novel-slug/",
  "message": "Imported as draft.",
  "items": [
    {
      "localType": "chapter",
      "localId": "chapter_1",
      "remoteId": "chapter_remote_1",
      "status": "created",
      "message": "Chapter imported."
    }
  ],
  "requestId": "novelforge:project_1:abcdef",
  "remoteIds": {
    "cover": "cover_123",
    "project": "work_123"
  }
}
```

Accepted aliases:

- `success` may be used instead of `ok`.
- `workId` or `bookId` may be used instead of `remoteBookId`.
- `preview_url` and `publish_url` may be used instead of camelCase URL keys.
- `remote_ids` may be used instead of `remoteIds`.
- `request_id` may be used instead of `requestId`.
- `changedItems` may be used instead of `items`.

Item status values:

- `created`
- `updated`
- `skipped`
- `failed`

Remote ID rules:

- Novel work: `work_{contentEntryId}`
- Chapter: `chapter_{contentEntryId}`
- Cover: `cover_{seriesContentEntryId}`

Preview URL:

```text
https://wwwstationcat.org/admin-v2/?contentId={contentEntryId}
```

Publish URL:

```text
https://wwwstationcat.org/{localeSegment}/works/{seriesSlug}/
```

## Error Response

```json
{
  "ok": false,
  "error": {
    "code": "NOVELFORGE_TOKEN_INVALID",
    "message": "Invalid publish token."
  }
}
```

The app also accepts:

```json
{
  "message": "Invalid publish token.",
  "errors": [
    {
      "message": "Chapter 3 is missing body text."
    }
  ]
}
```

Common website error codes:

- `NOVELFORGE_TOKEN_NOT_CONFIGURED`
- `NOVELFORGE_TOKEN_INVALID`
- `NOVELFORGE_CONTRACT_HEADER_UNSUPPORTED`
- `NOVELFORGE_CONTRACT_UNSUPPORTED`
- `NOVELFORGE_PACKAGE_UNSUPPORTED`
- `NOVELFORGE_PROJECT_REQUIRED`
- `CONTENT_TABLES_NOT_READY`

## Phase 18B Behavior

- The app sends real HTTP requests only for Station Cat targets with API Base URL and Token configured.
- Successful responses save `previewUrl`, `publishUrl`, and remote ids into local publish records and sync state.
- Failed responses create a failed publish run and do not update sync hashes, so the same changes can be retried.
- The app does not upload cover images yet.
- The app does not automatically publish without explicit user-selected `publish` mode.
- Token values are masked in UI and are not written into request JSON.
